# 技术文档检索

## 工具边界

- 标准、规范、手册、原理、安装要求、技术指标和通用故障机理使用 `search_technical_documents`。
- 企业用气、用户档案、诊断结果、异常区间、设备健康、安防事件和工单等实时事实使用数据库查询工具。
- 同一问题同时包含技术要求和企业事实时分别调用对应工具，并在回答中区分“文档依据”和“业务数据”。

## 检索流程

1. 将当前问题和必要的多轮上下文补全为一个可独立理解的问题。
2. 保留用户原问题中的标准号、产品型号、部件名称、故障现象、数值、单位和限定条件，不得用推测替换。
3. 调用 `search_technical_documents`；不要把预期答案、无关聊天内容或数据库事实塞入 query。
4. 如果返回 `status=unavailable`，停止检索并明确说明本次未取得文档证据。
5. 如果结果为空或明显未覆盖核心对象，可换用规范名称、同义术语或“对象 + 任务 + 条件”的表达重试一次；第二次仍无有效证据时停止。

## 回答与引用

- 仅依据工具返回的 passages 陈述文档事实，并在对应句段使用 `[资料N]` 标注来源，最后列出：参考资料N：资料名。
- 不得把模型常识、企业数据库事实或用户说法伪装成文档结论。
- 多份资料一致时可以综合；存在冲突时分别说明各资料的表述和适用条件，不自行消除冲突。
- 区分强制要求、推荐做法、原理说明和故障推测；资料没有给出结论时明确说明证据边界。
- 回答用户当前问题即可，不罗列与结论无关的召回片段。

## 图片

- 只有图片能直接帮助理解当前答案时，才把工具提供的完整 Markdown 原样放在对应引用段落之后。
- 不修改图片 URL，不重复展示同一图片，跳过 Logo、封面和装饰图片。
- 知识库图片只用于页面展示，模型没有读取其像素；只能依据工具提供的标题、描述和相邻文本介绍图片。
- 用户直接上传的图片属于视觉输入，与知识库图片的处理规则不同。
